¡La Cohesión es Rey!
=====================

La cohesión es uno de los principios de diseño de ingeniería de software más fundamentales y clásicos. Se refiere al grado en que los elementos de cualquier **bloque de construcción** de arquitectura (**componente**, **módulo**, **subsistema**, paquete, etc.) *pertenecen* juntos.

La Cohesión es Difícil
=======================

Si fuera simple, no escribiríamos sobre ello... Qué *pertenece* junto dependerá de tu punto de vista - y podría ser diferente para varios stakeholders.

Debe haber reglas o principios consistentes y homogéneos para la cohesión dentro de tu sistema.

Agrupa Elementos que *Pertenecen* Juntos
=========================================

Algunos criterios para elementos que pertenecen juntos:

* Funciones o procesos de negocio similares
* Operan sobre datos similares
* Usados por usuarios similares
* Implementados en tecnologías similares o
* Siguiendo reglas/conceptos de implementación similares
* Desplegados de formas similares o en hardware similar
* Distribuidos o empaquetados de formas similares
* Implementados o mantenidos por las mismas personas
* <tú-nómbralo>
