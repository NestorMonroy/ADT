Glosario: Sección 02 - Restricciones

:Sección: 02 - Constraints (Restricciones)
:Términos: 23

Este glosario contiene los términos técnicos clave de la sección de restricciones.

----

Términos Principales
====================

.. glossary::

   Constraint
   Restricción
      Limitación que restringe las opciones de diseño, implementación o 
      desarrollo de un sistema. Puede ser técnica, organizacional o política.
      
      **Ejemplo:** "El sistema debe usar Java 17 como mínimo" (restricción técnica).

   Organizational Constraints
   Restricciones Organizacionales
      Limitaciones relacionadas con la organización, como tiempo, presupuesto, 
      recursos humanos, procesos de desarrollo, contratos con terceros, o 
      asuntos legales.
      
      **Ejemplo:** "El proyecto debe completarse en 6 meses con 3 desarrolladores".

   Technical Constraints
   Restricciones Técnicas
      Limitaciones relacionadas con tecnología, hardware, plataformas, frameworks, 
      herramientas de construcción, o arquitecturas de referencia obligatorias.
      
      **Ejemplo:** "Debe desplegarse en contenedores Docker".

   Stakeholder
   Parte Interesada
      Persona u organización que tiene interés o puede ser afectada por el sistema. 
      
      **Nota:** En contexto técnico, frecuentemente se mantiene el término en 
      inglés "stakeholder".

   Build Tool
   Herramienta de Construcción
      Software que automatiza el proceso de compilación, empaquetado y pruebas.
      
      **Ejemplos:** Gradle, Maven, npm, Make.

   Framework
      Marco de trabajo de software que proporciona funcionalidad genérica.
      
      **Nota:** Término mantenido en inglés por ser estándar en la industria.

   Open-source License
   Licencia Open-Source
      Licencia de software que permite el uso, modificación y distribución 
      del código fuente libremente.
      
      **Ejemplos:** MIT, Apache 2.0, GPL, BSD.
