Consejo 1-1: ¡Proporciona un resumen compacto de requisitos!
============================================================

:Categoría: Requisitos
:Audiencia: Arquitectos, Desarrolladores




Contexto
========

Para varios lectores, la sección 1.1 de arc42 será lo primero que aprendan 
sobre el sistema.




Recomendación
=============

Aquí debes expresar los objetivos del negocio o del proyecto de manera clara 
y concisa. Da una breve descripción general de qué problema resuelve el sistema.

.. note::
   A veces un documento de requisitos se relaciona con más que el sistema 
   individual que describimos en la documentación de arquitectura.

Si el alcance del proyecto y el alcance del sistema son diferentes, debes 
enfocarte solo en las partes de los requisitos que se aplican a este sistema.

Limítate a lo que es realmente importante, la esencia del sistema.

**Nuestra regla general:** Menos de una página, si es posible. Esta página 
puede contener un diagrama si apoya el contenido. Debes referenciar documentos 
de requisitos si están presentes.




Excepciones
===========

.. note::
   En algunos casos probablemente necesitas escribir más:

- Para sistemas con requisitos de negocio complejos o extensos
- Para sistemas sin una documentación de requisitos existente (y razonable)
